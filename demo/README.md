# SIMPS Demo Data Generator

This package provides a deterministic, reproducible demo dataset and CLI tooling to attach and remove demo data on demand without ever touching or corrupting real production records.

---

## 1. Quick Start

### Load Demo Data
Populates categories, departments, suppliers, users across all roles, 30 realistic items, 60 days of movement ledger history, purchase requests across all statuses, purchase orders, and in-app notifications.

```bash
npm run demo:load
```

If demo data already exists in the database, `demo:load` will safely refuse to prevent accidental duplicates. To overwrite existing demo data with a clean set:

```bash
npm run demo:load -- --reset
```

### Inspect Demo Status
Displays a table of record counts per table, broken down by Demo rows (`is_demo = 1`) and Real rows (`is_demo = 0`).

```bash
npm run demo:status
```

### Remove Demo Data
Safely deletes all rows with `is_demo = 1` in foreign-key-safe dependency order. Real records are byte-for-byte untouched.

```bash
npm run demo:clear
```

In a production environment (`NODE_ENV=production`), `demo:clear` refuses to execute unless explicitly passed `--force`:

```bash
npm run demo:clear -- --force
```

## 3. Demo Day Workflow Guide

1. **Before Demo Presentation:**
   ```bash
   # 1. Start application
   npm run dev

   # 2. Attach demo data
   npm run demo:load
   ```
   Open the browser at `http://localhost:5173`. Notice the amber banner **"Demo data loaded — Clean up before real use: npm run demo:clear"**.

2. **During Demo Presentation:**
   - Log in as `principal@demo.invalid` to showcase executive analytics and pending HoD requisitions.
   - Log in as `officer@demo.invalid` to demonstrate purchase order generation.
   - Log in as `sales@apex.demo.invalid` to demonstrate supplier workflow.
   - Log in as `storekeeper@demo.invalid` to demonstrate goods receipt and inventory valuation.

3. **After Demo Presentation (Cleanup):**
   ```bash
   npm run demo:clear
   ```
   Verify that all demo rows are completely removed and the amber demo banner disappears immediately.

## 4. Integrity and Safety Guarantees

- **Rule 2 Compliance:** Every row generated by `demo:load` has `is_demo = 1`.
- **Inheritance:** When normal application logic acts upon a demo record (for example, issuing stock from a demo item, approving a demo request, or receiving a demo PO), the newly generated ledger movement or notification inherits `is_demo = 1`.
- **Zero Orphans:** `demo:clear` removes children and cascades in strict foreign-key order without leaving orphaned rows.
- **Production Guard:** Refuses deletion if `NODE_ENV=production` without `--force`.
- **Self-Check:** `demo:load` automatically runs an invariant verification suite validating stock quantities, ledger sums, and foreign keys before reporting success.
